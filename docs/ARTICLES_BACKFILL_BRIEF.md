# Бриф: закачати всі старі СТАТТІ в нору

Промт для окремої сесії. Контекст прочитай тут і в зазначених файлах — у
самій задачі нічого вигадувати не треба, лише акуратно реалізувати.

---

## Задача

Разово долити в нору (дзеркало архіву, Postgres бота, таблиця `articles`)
всі **історичні статті** сайту — `nodes.type = 'article'` — яких там немає.

## Звідки взялась дірка (стан на 30.07.2026)

- Нора з народження дзеркалила ЛИШЕ `type='news'`. 30.07 фільтр розширено на
  `type IN ('news', 'article')` (`handlers/archive_mirror.py`), у таблицю
  `articles` додано колонку `kind` (`news`/`article`, дефолт `news`), URL-білдери
  навчено статей (`/articles/{slug}`), а `/nora_resync <id|URL>` вміє затягнути
  конкретну статтю.
- Щогодинний інкремент (`:50`) підхоплює лише рядки з
  `GREATEST(updated, published) >= mirror_cursor` — тобто НОВІ й щойно
  оновлені статті синкаються самі, а історичні (їх торкались роками тому) не
  заїдуть ніколи.
- Головний бекфіл (`/archive_backfill`, курсор `backfill_last_id` у
  `sync_state`) уже пройшов усі id до кінця зі СТАРИМ фільтром — статті він
  проминув, і повторний запуск нічого не дасть: `reached_end` давно настав,
  курсор стоїть на максимумі.

## Що треба зробити

Окремий разовий бекфіл статей — за зразком наявного `backfill()` в
`handlers/archive_mirror.py`, але:

1. **Свій курсор** у `sync_state` (напр. `articles_backfill_last_id`) — НЕ
   чіпати `backfill_last_id`, `mirror_cursor`, `backfill_done_at`: вони
   тримають основний бекфіл та інкремент, і їх зсув зламає дзеркало.
2. Вибірка: `WHERE type = 'article' AND status = 1 AND published > 0 AND
   published <= now AND id > cursor ORDER BY id LIMIT batch`.
3. Перевикористати `_sync_rows` (він уже вміє upsert + теги + kind) і повагу
   до лімітів KEY4: батчі `BACKFILL_BATCH`, пауза `BACKFILL_PAUSE`, одне
   з'єднання на весь прогін (`conn=`), resumable після /archive_stop чи
   редеплою.
4. Команда бота `/articles_backfill [N]` (whitelist `ALLOWED_USER_IDS`, як
   `/archive_backfill`): N — порція за запуск, без N — до кінця; прогрес
   повідомленням, підсумок з кількістю і діапазоном id.
5. Після завершення статей у норі, ймовірно, кілька тисяч (проти ~200к
   новин) — прогін має бути справою хвилин, але ліміти БД сайту
   (10000 запитів/год, 5 конекшенів) поважати обов'язково.

## Перевірка результату

- `/archive_status` і `/nora_sql SELECT kind, COUNT(*) FROM articles GROUP BY kind`
  — має зʼявитись помітна купка `article`.
- `/nora_sql SELECT id, title_ua FROM articles WHERE kind='article' ORDER BY id DESC LIMIT 5`
  — свіжі статті на місці.
- FTS: спитати Лиса «що ми писали про X» по темі, де точно була стаття, —
  стаття має зʼявитись у видачі З ПРАВИЛЬНИМ URL `/articles/…`.
- Конкретний маркер: стаття **311397** («Як Миколаїв змінити підхід до захисту
  історичної забудови») має бути в норі — саме з неї дірку і знайшли.

## Що чіпати НЕ треба

- `entity_layer` — сутності зі статей доберуться пізніше окремим
  `/entity_backfill` за діапазон дат (платно, це рішення Олега, не твоє).
- Основні курсори дзеркала (див. п.1).
- CMS-специфіку чистки текстів: `html_to_text` і `_row_to_tuple` вже
  відпрацьовані на 200к новин, для статей нічого не міняти.
